# AnVir Next

Нативный рабочий прототип монитора Windows 11 x64 на Rust.

## Первая версия

- Числовые иконки загрузки CPU, температуры CPU и процента занятой памяти; графические иконки сети и диска. Набор настраивается в меню.
- Таблица x64/x86 процессов: продукт, CPU, I/O, рабочий набор памяти, компания, путь и PID; поиск и сортировка.
- По выбору процесса — полная командная строка с аргументами, родитель, приоритет и маска CPU. Текст можно выделять и копировать.
- Изменение приоритета и affinity с явным сохранением правила для будущих запусков этого `.exe`. Правила сопоставляются по полному пути; проверка новых запусков — раз в две секунды.
- Автозагрузка: Run/RunOnce x64 и WOW64, пользовательская и общая папки Startup, задачи при запуске/входе, автоматические службы. Поддерживаемые Run/Startup/задачи можно включать и выключать; RunOnce и службы доступны для чтения.
- В фоне отслеживаются изменения Run/Startup и StartupApproved. Задачи и службы перечитываются при открытии/обновлении списка. Неизвестные состояния и отказы доступа явно показываются.
- Аппаратные датчики из актуального LibreHardwareMonitor. Недоступные температуры показываются как «—».
- Нативные Win32-контролы, без браузерного движка и локального HTTP-сервера.
- Подробный опрос процессов выполняется при видимой, несвёрнутой вкладке процессов либо при наличии правил для будущих запусков.
- Закрытие окна оставляет мониторинг в трее; команда «Выход» завершает приложение.

## Сборка

Нужны Rust stable x64 MSVC, Visual C++ Build Tools с Windows SDK и .NET Framework 4.7.2 или новее. В Windows 11 .NET Framework уже доступен.

```powershell
.\scripts\build.ps1
```

Скрипт получает официальный LibreHardwareMonitor v0.9.6, проверяет SHA-256 из метаданных GitHub, собирает компонент датчиков и переносимую версию в `dist\AnVir-Next`.

Сборка только компонента датчиков, без Rust:

```powershell
.\scripts\build.ps1 -SensorsOnly
```

Проверки:

```powershell
.\scripts\test-sensor-protocol.ps1
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

## Датчики

Используется библиотека [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor), а не старый OpenHardwareMonitor из AnVir. Библиотека работает в отдельном процессе и передаёт только последние показания по локальному каналу. Полный интерфейс LibreHardwareMonitor для этого не запускается.

Для некоторых CPU/платформенных датчиков нужны драйвер PawnIO из официального комплекта и права доступа к нему. Приложение не устанавливает драйвер и не запрашивает повышение прав автоматически. Для явного перезапуска с повышенными правами есть команда в меню настроек. Недоступные значения показываются как отсутствующие; нули из недоступных низкоуровневых CPU-счётчиков отбрасываются. После установки драйвера приложение нужно перезапустить.

Антивирусные исключения не требуются для сборки и не настраиваются скриптами. Ничего из карантина AnVir не восстанавливается.

## Настройки

Настройки текущего пользователя хранятся в `%LOCALAPPDATA%\AnVirNext\settings.json`. Автозапуск меняется только явным действием пользователя в меню. Настройки существующего AnVir остаются самостоятельными.

Правила процессов хранятся в соседнем `process-rules.json`. Сохранение меняет выбранный процесс и будущие запуски этого файла, не затрагивая уже работающие соседние экземпляры. Время активации сохраняется вместе с правилом. При чтении старого формата без этого времени отсчёт начинается с текущего запуска монитора. Правила применяются в течение примерно двух секунд после обнаружения процесса; это не перехват до выполнения первой инструкции. Для многоядерных систем за пределами одной группы процессоров affinity пока не поддерживается. Память в таблице — резидентный рабочий набор, включая общие страницы; I/O включает файловые и другие операции устройств.
