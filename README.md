# AnVir Next

Нативный рабочий прототип монитора Windows 11 x64 на Rust.

## Первая версия

- Иконка CPU с голубыми столбцами физических ядер на чёрном фоне и полупрозрачным общим процентом. Сеть показывает вход слева и выход справа по активным физическим Ethernet/Wi-Fi/WWAN-адаптерам. У диска слева чтение, справа запись. Набор значков настраивается в меню.
- При наведении на значки CPU, памяти, сети и диска видны до трёх ведущих процессов по каждой метрике. Для сети приём и отправка ранжируются отдельно по локальным адресам активных физических адаптеров. Подсказка диска показывает занятость и скорости по накопителям и отдельные списки по чтению и записи.
- Таблица x64/x86 процессов: продукт, CPU, отдельные чтение/запись физического диска и приём/отправка сети, рабочий набор памяти, аргументы командной строки, компания, путь и PID; поиск и сортировка.
- По выбору процесса — полная командная строка с аргументами, родитель, приоритет и маска CPU. Текст можно выделять и копировать.
- Изменение приоритета и affinity с явным сохранением правила для будущих запусков этого `.exe`. Правила сопоставляются по полному пути; проверка новых запусков — раз в две секунды.
- Автозагрузка: Run/RunOnce x64 и WOW64, папки Startup, задачи при запуске/входе, автоматические службы. В таблице можно выделить несколько строк с Ctrl/Shift или все видимые строки с Ctrl+A. Контекстное меню позволяет запускать и останавливать записи и менять состояние поддерживаемых источников.
- Run/Startup отслеживаются по уведомлениям Windows. Фоновое сканирование раз в минуту подхватывает изменения задач и служб. Столбец «Когда добавлено» показывает время первого обнаружения. Записи, которые уже были в первой инвентаризации, показывают «—». Даты сохраняются в `startup-history.json` рядом с настройками.
- Аппаратные датчики из актуального LibreHardwareMonitor. Недоступные температуры показываются как «—».
- Нативные Win32-контролы, без браузерного движка и локального HTTP-сервера.
- Светлая/тёмная тема автоматически следует настройке приложений Windows и переключается без перезапуска; контрастный режим использует системные цвета.
- Дерево источников автозагрузки с группами реестра, пользовательских/общих папок Startup, папок Планировщика и служб. Иконки приложений и контекстные меню доступны в процессах и автозагрузке.
- При обновлении процессов сохраняются выделение и прокрутка. Пока курсор или контекстное меню находится над таблицей, порядок строк стабилен, а значения продолжают обновляться.
- Delete в таблице процессов завершает выбранный процесс после подтверждения. В автозагрузке Delete отключает поддерживаемую запись после подтверждения; уже отключённые записи не включает. В текстовых полях клавиша сохраняет обычное редактирование.
- Подробный опрос процессов выполняется при видимой, несвёрнутой вкладке процессов либо при наличии правил для будущих запусков.
- Аргументы собираются при открытой вкладке процессов и сохраняются с идентичностью PID + время создания; длинные строки отображаются без полного копирования при перерисовке. Их можно искать и копировать из контекстного меню.
- Сбор данных для подсказки начинается при наведении. Сеть и диск используют события Windows, пока видна вкладка процессов или курсор находится на соответствующем значке.
- Закрытие окна оставляет мониторинг в трее; команда «Выход» завершает приложение.

## Сборка

Нужны Rust stable x64 MSVC, Visual C++ Build Tools с Windows SDK и .NET Framework 4.7.2 или новее. В Windows 11 .NET Framework уже доступен.

```powershell
.\scripts\build.ps1
```

Скрипт получает официальный LibreHardwareMonitor v0.9.6, проверяет SHA-256 из метаданных GitHub, собирает компонент датчиков и переносимую версию в `dist\AnVir-Next`.

Сборка только компонента датчиков, без Rust:

```powershell
.\scripts\build.ps1 -SensorsOnly
```

Проверки:

```powershell
.\scripts\test-sensor-protocol.ps1
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

## Выпуск на GitHub

Обнови версию в `Cargo.toml`, `Cargo.lock`, `assets/app.manifest` и `assets/app.rc`, затем отправь коммит и тег той же версии.

```powershell
git push origin main
git tag -a v0.1.6 -m "AnVir Next v0.1.6"
git push origin v0.1.6
```

GitHub Actions соберёт `dist\AnVir-Next`, упакует папку целиком и опубликует ZIP в Releases. Описание релиза формируется из коммитов после предыдущего тега версии.

Сборку для существующего тега можно запустить в **Actions → Release → Run workflow**.

## Датчики

Используется библиотека [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor), а не старый OpenHardwareMonitor из AnVir. Библиотека работает в отдельном процессе и передаёт только последние показания по локальному каналу. Полный интерфейс LibreHardwareMonitor для этого не запускается.

При обычном запуске приложения Windows запрашивает повышение прав через UAC. Для части CPU и платформенных датчиков нужен драйвер PawnIO из официального комплекта. После установки драйвера приложение нужно перезапустить. Недоступные показания обозначаются «—».

Антивирусные исключения не требуются для сборки и не настраиваются скриптами. Ничего из карантина AnVir не восстанавливается.

## Настройки

Настройки текущего пользователя хранятся в `%LOCALAPPDATA%\AnVirNext\settings.json`. Автозапуск меняется только явным действием пользователя в меню. Настройки существующего AnVir остаются самостоятельными.

Правила процессов хранятся в соседнем `process-rules.json`. Сохранение меняет выбранный процесс и будущие запуски этого файла, не затрагивая уже работающие соседние экземпляры. Время активации сохраняется вместе с правилом. При чтении старого формата без этого времени отсчёт начинается с текущего запуска монитора. Правила применяются в течение примерно двух секунд после обнаружения процесса; это не перехват до выполнения первой инструкции. Для многоядерных систем за пределами одной группы процессоров affinity пока не поддерживается. Память в таблице — резидентный рабочий набор, включая общие страницы.

Скорости сети процессов учитывают TCP/UDP IPv4/IPv6, включая локальные и VPN-соединения, и могут отличаться от физических байтов в трее. Диск — завершённые операции физического диска: чтения из файлового кэша не считаются; отложенная запись может относиться к системному процессу, который её выполнил. Первое измерение требует интервала для расчёта скорости. Недоступные или непроверенные данные не подменяются нулями.

## Зависимости

AnVir Next распространяется по лицензии MIT. LibreHardwareMonitor и его компоненты распространяются по своим лицензиям, которые входят в папку `hardware-monitor` рядом с библиотеками.
